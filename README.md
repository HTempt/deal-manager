# 跟客 · 客户跟进管理工具

跟客（Genke）是面向个体老板、小微企业销售和服务行业从业者的**AI 客户跟进助手**：客户来了以后，不让他被忘记。本工程根据《跟客微信小程序 MVP 产品设计》实现，包含微信原生小程序、Spring Boot API、MySQL 自动迁移及 AI 话术服务。产品聚焦客户跟进过程，成交数据保留为明确的业务结果，用于记录和复盘。

## 品牌与命名

- 产品名统一为「跟客」；一句话定位「客户跟进管理工具」，产品定位「AI 客户跟进助手」。
- 对外文案统一使用「跟客」品牌和「AI 客户跟进助手」定位；「客户来了以后，不让他被忘记」表达核心价值，文档、小程序标题、会员页与“关于”弹窗不出现旧品牌名。
- 内部标识保持原样，不属于对外品牌：Java 包 `com.dealmanager`、Maven 构件 `deal-manager-api`、数据库名 `deal_manager`、仓库目录、日志文件名 `deal-manager.log`。如后续需要彻底更名，必须同步修改数据库名、部署脚本和历史 Flyway 脚本，建议单独排期。
- 微信公众平台的正式小程序名称、简介和服务类目需要在平台上设置，代码里只保留可运行默认值。

## 已实现

- 首页：今日待跟进、高意向、逾期、待安排统计、优先客户
- 客户：搜索/筛选、新增、编辑、详情、软删除、意向分
- 首页客户价值排序：“今日最值得跟进”综合意向、预计金额、今日/逾期计划、最新主动咨询、报价未回应记录及高价值沉睡机会，按客户去重展示前 10 位和真实推荐原因；金额权重封顶，尊重明确的未来跟进计划，无任务客户也能直接记录跟进。规则不调用 AI，无需新增数据库迁移，重启后端并重新编译小程序后生效。
- 每日 AI 工作建议：首页新增“今日建议”区块，每天首次打开时由模型从规则候选池中选出最值得重点跟进的客户（最多 5 位），给出 S/A/B 优先级和一句可直接执行的建议，例如“报价 ¥38,000，3 天未回复，建议今天下午电话联系”。模型只看到候选客户的真实资料：阶段、预计金额、意向分、完整未联系天数、待办是否逾期、最近反馈与主动咨询/询价信号、沉睡分组、人工标签和规则排序依据；候选池复用首页规则排序（尊重明天及以后的明确计划），模型不得推荐候选以外的客户，返回数量必须等于候选数上限，一个人只能出现一次，结构不完整或引用他人客户时显示错误、不保存旧结果也不扣次数。结果按北京日期和账号保存当天一份，资料变化后保留旧建议并提示“客户数据已更新，可重新生成”，点击“重新生成”才再次调用模型；当天没有候选客户时只显示事实提示，不调用模型。该功能不占用销售话术每日次数。后端 `POST /api/home/daily-advice?refresh=false`，Flyway `V12__daily_advice.sql` 建表。
- 意向评分：新增、编辑及记录跟进时按阶段、近期有效联系、最新反馈、主动咨询、询价、预计金额与有效跟进频率重新计算 0～100 分，不再累加固定分值；仅参考近 30 天记录，无回应不计有效联系，近 14 天频率按有回应的日期去重且最多 5 分。可切换人工评分并直接填写或拖动滑块修改，人工分数保留至主动切回综合评分；跟进记录保存评分方式和前后分数。后端启动执行 `V9__intention_scoring.sql`，已有客户保持原分数，到下一次跟进或编辑保存时重新评分。未自动调用 AI 评分。
- AI 客户摘要：详情顶部显示客户概况、当前建议、跟进次数和未联系天数。首次没有有效摘要时调用大模型生成并保存概况和当前建议，没有跟进记录也会基于已填写的客户资料分析。后续优先读模型结果缓存；资料、记录或全局 AI 设置变化后提示待更新，主动点击“更新客户摘要”按最新资料重新调用模型，失败保留旧摘要并显示可重试错误，不使用固定建议兜底。不重复要求确认已经填写的需求和预算，不编造沟通反馈。参考最近最多 30 条记录，不占销售话术每日次数，遵循全局 AI 设置；销售者行业和业务背景不作为客户职业或需求。
- 建议与话术统一由模型生成：客户概况、当前建议、跟进判断、建议动作、推荐话术、跟进间隔及依据、唤醒建议，以及有数据的经营小结均调用现有模型池。重写和缩短同样调用模型；成交或流失客户的文字依据来自模型，系统仅限制不创建销售跟进安排。模型失败或返回不完整时显示错误，保留已有结果并允许重试，不以模板替代。跟进助手输入包含最新需求、预算、标签和最近记录中的主动咨询、询价信号。无经营数据时只显示事实状态提示。
- 跟进：逾期/今日/即将跟进任务，未来任务按日期分组、跟进记录、自动完成旧任务并生成下次任务
- 待安排：发现没有下次跟进时间的有效客户，支持明天、3 天后和自定义时间快捷安排
- 沉睡客户：按北京时间完整未联系天数自动识别有效客户，7～14 天即将沉睡、15～30 天沉睡、31 天起长期沉睡；无跟进记录时从创建时间计算。首页显示沉睡总数（含长期沉睡），客户页按组筛选、搜索和分页查看。列表、详情与会员页可进入 AI 唤醒，生成联系理由、唤醒方式和话术，遵循全局 AI 设置与现有每日额度；记录新跟进后自动退出原沉睡分组，安排未来跟进不代表已联系。
- AI 跟进助手：结合客户资料与最近 5 次跟进记录生成当前判断、建议动作、推荐话术和下次跟进间隔；可确认采用建议时间生成任务，支持生成/重写/简短及可切换模型池，免费用户每天 10 次、有效 VIP 无限次数
- 成交：成交金额、日期、产品录入，自动取消客户待办
- 数据：月度新增、环比、成交客户/金额、来源分析，以及同月新增客户的累计销售漏斗和转化率。漏斗从新增客户依次展示需求沟通、方案中、报价中、谈判中、成交；统计所选月份新增、未删除客户截至当前的最高阶段，同一客户只计一次，不混用历史客户当月成交。成交转化率=该批客户已成交数/该批新增客户数，报价到成交=该批已成交数/该批达到报价及以后阶段的客户数，零分母显示暂无数据。跳过阶段视为经过前置阶段，阶段回退或流失不抹掉此前进展。后端新增 `GET /api/data/funnel?month=YYYY-MM`，Flyway `V11__customer_funnel.sql` 保存累计最高阶段；历史数据按当前阶段回填，旧已流失客户此前阶段无法恢复。漏斗不是月末快照，后续成交会更新对应新增月份的转化率，与顶部按成交日期统计的当月金额/成交客户口径不同。
- 经营复盘：按用户和月份保存到 `business_summary` 表，进入页面优先读取已保存结果，仅没有结果时调用现有模型池并落库；业务数据更新后可点击“重新分析”生成并覆盖结果，失败保留旧复盘。无经营数据不调用模型，不占用销售话术每日次数。后端启动时 Flyway 自动执行 V3 建表迁移。
- 跟进效率：数据页重组为月度概况、转化、跟进效率、来源与经营复盘。新增咨询→报价转化率和 `GET /api/data/follow-efficiency?month=YYYY-MM`，展示已到期应跟进任务数、完成数/率、未完成数、按当月实际联系客户计算的平均跟进次数，以及按首次成交去重的平均成交周期；显示样本量，无样本显示“—”，取消和未到期任务不进入完成率分母。AI 小结接入真实转化与效率数据，旧分析保留并提示手动重新分析。本次无需新增数据库迁移，重启后端并重新编译小程序即可使用。
- 我的：行业设置、AI 设置、会员用量与会员展示页
- 全局 AI 设置：统一管理风格、称呼、长度、业务介绍、业务优势与常用表达，应用于跟进助手的所有文字、客户摘要和经营小结。每次生成读取当前账号的最新偏好；旧摘要保留并提示待更新，不因保存设置自动消费模型调用。
- 提醒开关：我的 → 提醒设置 → 微信跟进提醒，默认关闭，按账号保存；关闭时阻止后端发送和业务保存后的订阅授权提示。开启后可点击“订阅提醒”申请微信授权，开关开启不等于微信已授权或消息已送达。
- 安全：JWT 登录态、所有业务查询按当前用户隔离、后端强制免费额度

## 启动后端

要求 Java 17+、Maven 3.9+。数据库密码、JWT 密钥等敏感信息不写入仓库，请通过环境变量传入。

PowerShell：

```powershell
cd backend
$env:DB_HOST='localhost'
$env:DB_PORT='3306'
$env:DB_NAME='deal_manager'
$env:DB_USERNAME='root'
$env:DB_PASSWORD='<数据库密码>'
$env:JWT_SECRET='<至少 32 字节的随机字符串>'
mvn spring-boot:run
```

首次启动会由 Flyway 自动创建 `deal_manager` 数据库结构和行业配置。也可以在项目根目录设置同名环境变量后运行：

```powershell
docker compose up --build
```

## 接入真实 AI

AI 模型统一在 `backend/ai-models.json` 配置：主模型为 ModelScope `Qwen/Qwen3.8-27B`，备用模型为 Heju API `gpt-6.1-sol`，备用已启用。该文件包含密钥并被 Git 忽略，启动目录为根目录或 backend 均会自动加载。不要复制进小程序或提交版本库。所有 `.env` 文件及其变体仅在本地保留，不提交版本库。生产环境仍可使用环境变量覆盖。

### 模型池与额度切换

模型池 ID、启用状态、实际模型名称、接口地址、密钥及优先模型全部在 `backend/ai-models.json` 维护。顶层 `activeModel` 选择优先模型，`pool` 数组每项包含 `id/enabled/baseUrl/model/apiKey`。新增模型直接追加一个对象，不用修改 `application.yml`。可用环境变量 `AI_MODELS_FILE` 指定外部 JSON 路径。

切换到备用模型：将 JSON 的 `activeModel` 改为 `"backup-model"`（或 `"gpt-6.1-sol"`），然后重启后端。切回主模型改为 `"modelscope-qwen"`。环境变量 `AI_ACTIVE_MODEL` 也可以覆盖默认优先项。

主模型限额耗尽、鉴权或服务异常时自动尝试其他已启用模型。所有模型失败不扣用户次数，记录实际成功模型与 token 用量。

Docker Compose 只读挂载同一份本地模型配置，不再单独维护一套 AI 配置。供应商总账号额度耗尽时，同一 Token 切换模型未必能恢复，需要另一个有额度的供应商/Token。

游客（FREE）每日 10 次，按北京时间零点重置；有效 VIP/PRO 不限制应用内次数（供应商自身限额仍适用），已过期会员恢复免费额度。生成、重新生成、更简短均成功后计一次。无内容、重生内容相同、简短未缩短或调用失败不扣次数。按用户数据库行锁串行生成，防止多端并发超用。

AI Key 仅保存在后端，小程序不会接触密钥。跟进助手的判断、动作、话术和跟进间隔均由 LLM 生成并校验结构化 JSON；模型返回缺失字段或无效格式时尝试备用模型，最终失败不扣次数。有效客户的间隔须为 1~30 天，建议时间按北京时间对应日期 10:00 生成。只有用户确认“采用跟进时间”后才更新客户计划和待处理任务，已有计划会提示覆盖；已成交或已流失客户不提供可采用的销售跟进时间。历史 AI 记录保留完整结构化建议与实际模型、token 用量。

## 模型调用入库

后端启动时 Flyway 自动执行 `V10__model_call_log.sql`，新增 `model_call_log` 表。统一在模型池客户端记录每次实际调用，覆盖跟进助手生成/重写/缩短、客户摘要、唤醒建议和经营小结；缓存命中或无经营数据时不会产生模型调用记录。

- 入口：`entry_point` 保存 HTTP 方法和接口路由（非 HTTP 调用为 `INTERNAL`），`action` 保存业务操作；同时保存 `request_id` 和当前认证 `user_id`。
- 输入输出：`input_text` 保存真正发给模型的完整 JSON（含系统提示、用户提示和生成参数），`output_text` 保存原始 HTTP 响应，`response_content` 保存提取的模型正文。不会主动保存 Authorization 请求头、模型密钥或接口地址。
- 调用信息：供应商/模型、尝试序号、成功或失败状态、HTTP 状态码、token 用量、开始/结束时间（北京时间）、耗时毫秒、错误原因和异常类型。
- 主模型失败后切换备用模型时，每次尝试各保存一条，以相同 `invocation_id` 关联。无有效模型配置时保存 `attempt=0` 的诊断记录；网络失败没有响应时输出为空，返回了无效结构或错误响应时仍保留原文。
- 日志通过独立事务提交，业务失败回滚不会删除已发生的模型调用记录；不影响原 `ai_record` 的成功消费记录和免费额度计算。日志入库失败会产生 `ai.call_log.save_failed` 错误日志，但不会为了重试写日志重复调用付费模型。

排查示例（直接在数据库执行）：

```sql
SELECT id, invocation_id, entry_point, action, provider, model, attempt,
       status, http_status, token_usage, duration_ms, error_reason, started_at
FROM model_call_log
ORDER BY id DESC
LIMIT 100;

SELECT * FROM model_call_log WHERE invocation_id = '<调用编号>' ORDER BY attempt;
SELECT * FROM model_call_log WHERE request_id = '<X-Request-Id>' ORDER BY id;
```

**数据安全**：该表有意保存客户资料、完整提示词和模型原文，应限制数据库读取权限并按业务合规要求定期清理。当前未增加对小程序开放的日志查询接口，也未自动删除调用记录；控制台和文件日志仍不输出完整正文。上线时请评估保存期限和存储增长。

## 后端日志

日志默认同时输出到启动控制台和 `logs/deal-manager.log`（相对后端进程的工作目录；从 `backend` 启动时为 `backend/logs/deal-manager.log`）。按日期和 20MB 文件大小滚动压缩，保留 14 天，归档总量最多 1GB。重启后端后生效。

每个请求生成 `requestId`，响应头返回 `X-Request-Id`；接口、业务与 AI 调用日志共用此编号，认证后带内部 `userId`。记录接口路径、状态码和耗时，4xx 使用 WARN、5xx 使用 ERROR，超过 3 秒的请求标记 `slow=true`。异常日志保留异常类型、调用栈和数据库 SQLState/错误码，省略可能含密钥或客户资料的原始异常信息。

客户摘要可按 `customer_summary.requested` → `cache_hit` 或 `generating` → `ai.model.started` → `ai.model.completed/failed` → `customer_summary.saved` → `http.request.completed` 排查。AI 日志包含操作、模型、尝试次数、耗时、token 用量及备用模型状态；失败原因包括 `HTTP_429`、`HTTP_401`、`HTTP_5xx`（实际状态码）、`TIMEOUT`、`CONNECTION_FAILED`、`INVALID_RESPONSE` 和 `OUTPUT_TRUNCATED`。缓存命中时记录是否待更新，不会调用模型。业务保存日志记录数据库操作完成，最终是否提交成功以请求完成或异常日志为准。

同时记录客户新增/修改/删除/安排、跟进和成交保存、设置修改、登录、通知发送及通知记录保存失败。默认不输出完整 SQL、请求/响应正文、提示词、生成原文、手机号、微信登录凭证、JWT 或模型密钥；通知轮询无任务或未配置的诊断放在 DEBUG，避免反复刷屏。

可通过 `LOG_FILE` 修改日志文件路径，`APP_LOG_LEVEL=DEBUG` 开启应用诊断日志，`SLOW_REQUEST_MS` 调整慢请求阈值。SQL mapper 保持 WARN，不随应用 DEBUG 输出客户参数。

```powershell
# 从项目根目录实时查看日志
Get-Content .\backend\logs\deal-manager.log -Tail 100 -Wait

# 查找某次请求的全部日志
Select-String -Path .\backend\logs\deal-manager.log -Pattern '对应的请求编号'
```

## 上线前仍需平台配置

每日 AI 工作建议使用 Flyway `V12__daily_advice.sql` 新增 `daily_advice` 表，按账号和北京日期唯一；客户位置字段由 `V13__customer_location.sql` 迁移增加。更新后重启后端执行迁移，并在微信开发者工具重新编译小程序；同一天重复打开首页读取已保存结果，只有点击“重新生成”才再次调用模型。该表保存当天建议、候选快照指纹和完整提示词，请与 `model_call_log` 一起纳入数据保留期限评估。

全局 AI 设置兼容使用 Flyway `V7__global_ai_preferences.sql`，为经营小结保存生成时的设置指纹。重启后端执行迁移后，旧小结会提示待重新分析；点击“重新分析”按最新偏好生成并保存。客户摘要也会将全局设置纳入资料指纹，设置变化后提示“摘要待更新”。重新编译小程序可显示更新提示和“AI 全局设置”标题。

客户摘要使用 Flyway `V6__customer_summary.sql` 新增 `customer_summary` 表。更新后重启后端执行迁移，并在微信开发者工具重新编译小程序。摘要接口为 `POST /api/customers/{id}/summary?refresh=false`；显式更新使用 `refresh=true`，保存实际模型和 token 用量。摘要生成使用现有后端模型池，资料或记录变化后不会自动反复调用模型，需点击“更新客户摘要”；建议仅作参考，不会自动安排任务。

提醒开关使用 Flyway `V5__notification_setting.sql` 增加用户偏好字段。更新后重启后端让迁移和 `/api/notifications/settings` 接口生效，并在微信开发者工具重新编译小程序。实际订阅授权需要在 `miniprogram/config.ts` 配置 `FOLLOW_SUBSCRIBE_TEMPLATE_ID`，微信发送需要后端配置正式 `WECHAT_APP_ID` 和 `WECHAT_APP_SECRET`。

- 微信公众平台：正式 AppID、request 合法域名、用户隐私保护指引
- 服务器：HTTPS 证书、生产级 JWT 随机密钥、数据库最小权限账号
- 订阅消息：在公众平台申请模板后接入跟进提醒
- 微信支付：申请商户号后接通会员下单与支付回调；当前会员页只展示方案，不发起支付

数据库连接参数通过环境变量设置，参见上方启动说明。不要把真实密码、微信 Secret、AI Key 或任何 `.env` 文件提交到版本库。
